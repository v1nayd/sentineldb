## Caveats I want you to see, not just the fixes

- **The database enforces "no application SQL path may do X"; it cannot tell analyst from admin** (one DB account). Role rules (who edits assets, who closes incidents) are server code in M3. A stolen app credential can still call any procedure the account may execute, in the app's name. `Users` `SELECT` still includes `password_hash` because login needs it; M3 must prevent it ever reaching a client, with a test.
- `asset_type` and `created_by` immutability are **my policy choices**, not requirements from the spec. If the team wants asset reclassification, it is a one-line grant change plus a test change.
- Adding the library pins to the fingerprint changed it, so the collection name changed; any `incident_narratives__<old fingerprint>` collection in an existing dev Qdrant is now unused and can be deleted.
- The new tests are mutation-checked individually, but the suite is still only as strong as the cases it covers — the Users gap survived 10 passing tests for exactly that reason.
