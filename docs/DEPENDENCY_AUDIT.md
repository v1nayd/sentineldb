The "5 moderate" table below describes the M1 state and is kept as history; the zod 3→4 major bump needed no source change (only plain object/string/enum schemas are used). ## Remaining (5 moderate, one chain)

`@huggingface/transformers` → `onnxruntime-node@1.21.0` → `global-agent@3.0.0` → `roarr@2.15.4` → `sprintf-js@1.1.3` (GHSA-hp3w-g68c-fv3c, DoS via unbounded precision specifiers in a format string).

Reachability: `global-agent` is referenced only by `onnxruntime-node/package.json` and `onnxruntime-node/script/install.js` (its `postinstall` binary downloader); nothing under its runtime entry points imports it (grep of the installed package). So it executes on a developer/CI machine during `npm install`, never in the running server, and the vulnerable call needs an attacker-controlled format string. **Residual risk: low, install-time only.** Fix path: `@huggingface/transformers@4.x` (newer onnxruntime-node); I could not test it because its installer downloads from `api.nuget.org`, which is blocked in the build workspace. Retry on an unrestricted machine.

## Reachability of the fixed ones (why they mattered or not)

- **undici**: used by the Qdrant client for HTTP to the operator-configured Qdrant. Exploiting most advisories needs a malicious server/response or WebSocket use. Low practical exposure, but patching was a one-line override, so it was patched rather than argued away.
- **sharp**: imported by `@huggingface/transformers/src/utils/image.js` (image tasks only). Our code runs text feature-extraction only; no untrusted image ever reaches it.
